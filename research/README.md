# 業績ファイルの書き方

業績は **1件につき1ファイル** で，`research/<年>/` に置きます．
ファイルを追加・修正して `main` に取り込まれると（下の「リポジトリ編集時の注意」），数分でサイトに反映されます（HTML を書く必要はありません）．

```
research/
├─ 2024/
│   ├─ paper-202407.md     論文・会議発表など
│   └─ paper-202445.md
├─ 2025/
│   └─ award-51.md         受賞
├─ _template/              ひな形（コピーして使う．サイトには表示されない）
└─ index.json              全業績の一覧（GitHub Pages が自動で作る．編集しない）
```

## リポジトリ編集時の注意

`main`（公開されるブランチ）は保護されていて，**直接 push できません**．次の流れで反映します．

1. `feature/pre_release` ブランチに切り替え，pull して最新にする
2. 業績ファイルを追加・修正して `feature/pre_release` に push する
3. GitHub で `feature/pre_release` → `main` の Pull Request を作る
4. `system_admin` チームの誰かが承認したら，Merge する（数分でサイトに反映）

- `main` への Pull Request は **`feature/pre_release` からのものだけ** 受け付けます（それ以外は自動チェック `check-source-branch` が失敗して Merge できません）．
- 新しいブランチは作れません（全ブランチで作成が禁止されています）．`feature/pre_release` を使ってください．
- 承認には `system_admin` チーム（`.github/CODEOWNERS` で指定）のレビューが1件必要です．最後に push した本人の承認は数えられません．
- 承認後に追加で push すると承認は取り消されるので，もう一度承認をもらってください．
- Merge の方法は「Create a merge commit」のみです（Squash・Rebase は使えません）．
- `main` の削除・force push はできません．
- `system_admin` チームは上のルールを免除されています（緊急時の直接 push・ブランチ作成用）．ふだんは同じ流れで作業してください．

## 追加のしかた
1. 現在自分がいるブランチが`feature/pre_release`にいて，fetch, pullされて最新であることを確認する
2. `_template/` から種類に合うひな形をコピーし，`research/<年>/` に置く
3. ファイル名を `<種類>-<番号>.md` にする（例 `paper-202601.md`）
4. 中身の `""` の間に値を書く
5. `feature/pre_release` に push し，`main` への Pull Request を作る（上の「リポジトリ編集時の注意」）

| 種類 | ファイル名 | ひな形 |
|---|---|---|
| 論文・会議発表・解説など | `paper-<番号>.md` | `_template/paper-000000.md` |
| 特許 | `patent-<番号>.md` | `_template/patent-0.md` |
| 受賞 | `award-<番号>.md` | `_template/award-0.md` |
| 取材記事・TV など | `media-<番号>.md` | `_template/media-0.md` |

- **ファイル名はサイト全体で重複しないようにしてください**（個別ページの URL になります．例 `research/2024/paper-202407.html`）．
- 年のフォルダは整理用です．一覧の年タブは中身の「日付」で決まります（特許は公開日，無ければ出願日）．

## 書き方のルール

```
---
タイトル: "LIBRA-I：小径孔を通過可能な内部調査用軽量長尺多関節アーム"
種別: "論文"
日付: "2024-03-22"
PDF: ""
---
```

- 先頭と最後の `---` は消さないでください．
- 1行に「項目名: "値"」を1つずつ書きます．**値は必ず `"` で囲んでください**（`:` などの記号が入っても壊れないように）．
- 値の中に `"` を書きたいときは `\"` と書きます．
- 空欄（`""`）の項目は，個別ページの表に表示されません．
- 日付は `"2024-03-22"` の形（月までなら `"2024-03"`）．
- 文字コードは UTF-8（VS Code やメモ帳で普通に保存すれば UTF-8 になります）．

## 項目

### 論文・発表（paper-）

| 項目 | 書き方 |
|---|---|
| タイトル | |
| 種別 | `論文` / `国際会議発表` / `国内会議発表` / `解説・総説` / `著作` / `その他` |
| 査読 | `査読あり` / `査読なし` |
| 著者 | 例 `杉原 怜, 遠藤 玄` |
| 言語 | `日本語` / `英語` |
| 掲載誌 | 学術誌名・会議名 |
| 巻号ページ | 例 `Vol. 92 No. 953 p. 25-00128`，講演番号のみなら `1A1-L07` |
| 日付 | 出版日（論文）または発表日（会議） |
| DOI | `10.1299/transjsme.25-00128` の形．あれば「論文を読む」ボタンが出る |
| URL | DOI が無いときの論文ページ（IEEE Xplore など）．あれば「論文を読む」ボタンになる |
| T2R2 | T2R2 の論文ページの URL（`https://t2r2.star.titech.ac.jp/cgi-bin/publicationinfo.cgi?q_publication_content_number=CTT…`）．記録用（ページには表示しない） |
| PDF | 本文 PDF ファイルの URL（T2R2 なら `https://t2r2.star.titech.ac.jp/rrws/file/CTT…/ATD…/`）．あればページ最下部に「PDFをダウンロード」ボタンが出る |

### 特許（patent-）

| 項目 | 書き方 |
|---|---|
| タイトル | 発明の名称 |
| 状態 | `登録` / `公開` / `出願`（一覧の小ラベルになる） |
| 発明者 / 出願人 | |
| 出願番号 / 出願日 / 公開番号 / 公開日 / 登録番号 / 登録日 | |

**公開してはいけない出願（未公開のものなど）は載せないでください．** 状態は `登録` / `公開` / `出願` のどれかにします．

### 受賞（award-）

| 項目 | 書き方 |
|---|---|
| タイトル | 賞の名前 |
| 受賞者 | |
| 日付 | 受賞日 |
| 表彰機関 | |
| 関連業績 | 対象の論文のファイル名の番号（例 `202407`）．複数なら `;` で区切る．特許などは `patent-40` のように書く |
| URL | 学会の受賞者一覧ページなど |

関連業績を書くと，**論文側のページの「受賞」欄にも自動で表示**されます（論文側に書く必要はありません）．

### 取材記事・TV など（media-）

| 項目 | 書き方 |
|---|---|
| タイトル | 記事・番組のタイトル |
| 種別 | `TV` / `全国紙` / `専門紙` / `Webメディア` など（一覧の小ラベルになる） |
| 媒体 | 新聞名・番組名など |
| 日付 | 掲載日・放送日 |
| URL | 記事のページ．あれば「記事を見る」ボタンが出る |

## 項目を増やしたいとき

新しい項目名を使う場合は，`research/index.json` の `keys` にも同じ名前を追加してください（追加しないと一覧データに入りません）．
表への表示のしかたは `js_includes/data.js` の `BUILDERS` で決めています．

## 手元で確認する

リポジトリのフォルダで `python tools/preview.py` を実行し，表示された URL をブラウザで開きます．
ファイルを保存してブラウザを再読み込みすれば反映されます．書き方の誤りはこのコマンドの画面に `[警告]` として出ます．
